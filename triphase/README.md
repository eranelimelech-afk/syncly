# TriPhase — Garmin fēnix 8 / 8 Pro watch face

A single-screen, data-dense Connect IQ watch face with 11 metrics permanently
on screen. Content never changes; **emphasis** does. 3–4 fields render at full
brightness based on time of day (morning / day / evening phases, boundaries
user-configurable, plus a `flat` mode), the rest recede to muted gray.

Built against spec v1.0 (TriPhase Watch Face — Build Specification).

## Building

Requires the Connect IQ SDK (9.2.0+ recommended) and a developer key:

```sh
monkeyc -o bin/TriPhase.prg -f monkey.jungle -y developer_key -d fenix847mm
# or in VS Code with the Monkey C extension: "Build for Device"
```

Run in the simulator with `connectiq` + `monkeydo bin/TriPhase.prg fenix847mm`.

> **This tree has not yet been compiled against a real SDK** (authored in an
> environment without the Connect IQ toolchain). Expect the first build to
> surface small API-signature fixes. Everything below flagged "verify" is from
> spec §13 and must be resolved during the first simulator/device spike.

## Project structure

```
manifest.xml              product ids, permissions, languages
monkey.jungle             build config, Hebrew resource overlay
resources/
  strings/strings.xml     English strings (default/reference language)
  settings/               properties.xml + settings.xml (generated, see below)
  drawables/              launcher icon
resources-heb/            Hebrew phone-app setting titles only (see §10 note)
source/
  TriPhaseApp.mc          app entry, complication subscriptions
  TriPhaseView.mc         onLayout / onUpdate / onPartialUpdate / sleep hooks
  layout/Geometry.mc      all coordinates, derived from dc dimensions
  layout/Painter.mc       palette + drawField/drawArc/drawTicks/drawWeekday
  data/Fields.mc          field descriptors + accessor fallback chains
  data/Phase.mc           emphasis engine (per-minute cached, wraps midnight)
  config/Settings.mc      typed settings reader with defaults
```

`resources/settings/*.xml` are generated by a helper script (11 slot pickers ×
12 metrics each); regenerate rather than hand-editing if the metric list
changes.

## Deliberate deviations / open items (spec §13)

1. **Product IDs** (`fenix8pro47mm` etc.) are taken from the spec verbatim and
   **must be checked against the installed SDK's `devices.xml`** — a wrong id
   means the face installs but never appears in the watch-face menu.
2. **HRV status**: no documented watch-face API. The sanctioned §5 substitution
   is implemented — the HRV metric renders Stress from `SensorHistory` and is
   labeled STRESS on screen so it never misrepresents its source. If a future
   SDK exposes HRV, wire it into `Fields._hrvValue` and restore the label.
3. **Training readiness**: dropped (not exposed), per spec.
4. **Fonts**: currently the nearest built-in fonts. The spec's custom bitmap
   fonts (Barlow Semi Condensed, tabular figures, per-size `.fnt` filtered to
   needed glyphs) are the next step; each slot descriptor in `Geometry.mc`
   carries its font, so swapping is one line per size. Re-check the §3 vertical
   ladder once real font metrics are known.
5. **Next event**: no native API. Falls back to the calendar-events
   complication where the device offers it, else `--`. The spec's
   companion-app channel is out of scope for this pass.
6. **Week number** in the date line is day-of-year/7 + 1, not ISO-8601. Swap in
   a proper ISO week calc if the off-by-one at year boundaries matters.
7. **Background**: the radial gradient is approximated with two concentric
   fills; the 1.5%-opacity carbon cross-hatch is omitted for now (spec §9 bans
   texture bitmaps; §14 rule 4 — decoration pays rent or leaves).
8. **On-device `WatchFaceConfig` editor**: not yet implemented; app-side
   settings are the complete, standalone set (required by spec §7 either way).
   Add the on-device editor for accent + emphasis mode after verifying current
   fēnix 8 Pro firmware no longer shows the spurious "use system watch face"
   message.
9. **Hebrew**: shipped as a phone-app-only overlay (setting titles). On-watch
   Hebrew labels need a custom bitmap font and on-hardware validation — the
   simulator does not render Hebrew at all (spec §10: "Ship English first").
